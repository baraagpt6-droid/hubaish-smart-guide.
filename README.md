# دليل مديرية حبيش

تطبيق ويب تقدمي عربي (PWA) مع حاوية Capacitor لتجهيز Android وiOS. ملفات التشغيل المنشورة موجودة في `www/`، ويديرها `www/app.js` و`www/features.js` و`www/styles.css`.

## الوظائف

- مظهر داكن افتراضي ومظهر نهاري، مع خطوط Reem Kufi وIBM Plex Sans Arabic.
- واجهة عربية وإنجليزية وتركية وفرنسية، مع ضبط اتجاه النص وحفظ اللغة محلياً.
- أقسام رئيسية للتاريخ والمعالم والعزل والمجتمع، مع بحث عربي مطبّع، بحث صوتي عند دعم المتصفح، تصفية، تفاصيل ومفضلة.
- قائمة من 22 اسماً للعزل وفق البيانات الإدارية المتاحة، مع إبقاء اختلافات التهجئة بين المصادر ضمن الاسم.
- مواقيت صلاة محسوبة تقريبياً لإحداثيات حبيش وبالتوقيت `Asia/Aden` (UTC+3).
- مساعد محلي يجيب من المحتوى المضمّن، واختبار معلومات، مساهمات، إدارة محتوى محلية، واستيراد/تصدير JSON.
- Service Worker وManifest للعمل دون اتصال بعد أول تحميل ناجح.
- تكامل Supabase اختياري للمحتوى المشترك وصندوق المساهمات. عند ضبط Project URL وPublishable key تتم مزامنة السجلات المعتمدة وتخزين نسخة محلية لاستمرار القراءة دون اتصال. المساهمات الجديدة تبقى pending حتى مراجعة المشرف.

## الدقة وحدود البيانات

- عدد السكان 105,998 يعود إلى تعداد 2004.
- مساحة المديرية غير محسومة بين المراجع التي تمت مراجعتها؛ تستخدم الواجهة 228 كم² في جدول OCHA/Local Governance وتذكر وجود مرجع محلي يورد 330 كم².
- الارتفاع والإحداثيات والمسافات تقريبية. رادار المسافة ليس نظام ملاحة GPS.
- مواقيت الصلاة تقديرية ويجب مطابقتها مع تقويم المسجد المحلي.
- لا توجد معلومات قرى موثقة لكل عزلة ضمن قاعدة النسخة الحالية. لا تعرض الواجهة أسماء قرى مختلقة.
- رواية تحرك 1919م موسومة بأنها تحتاج إلى مصدر مستقل.

## الخصوصية والإدارة

المفضلة وتفضيلات العرض وبعض بيانات الاستكشاف تحفظ في `localStorage` على الجهاز الحالي. عند ربط Supabase تُقرأ السجلات المعتمدة من قاعدة البيانات وتُخزّن نسخة محلية للعمل دون اتصال، وتُرسل المساهمات إلى صندوق وارد بحالة `pending` حتى يراجعها المشرف. إعداد Supabase غير مُفعّل افتراضياً؛ ملف `www/supabase-config.js` يحتوي قيماً فارغة إلى أن ينشئ مالك المشروع قاعدة البيانات ويدخل بياناتها العامة.

تستخدم الواجهة مفتاح Supabase العام `sb_publishable_` أو مفتاح `anon` القديم. لا تضع `sb_secret_` أو `service_role` في التطبيق أو المستودع. إدارة المحتوى المشترك تتطلب حساباً في Supabase Auth ودور `hubaish_admin` داخل `app_metadata`. رمز PIN المحلي يحمي أدوات الإدارة المحلية فقط ولا يمثل مصادقة سحابية.

## التطوير والتحقق

يتطلب Node.js 22 أو أحدث.

```bash
npm install
npm run build
npm run preview
```

`npm run build` يتحقق من الملفات والمراجع والـ Manifest وService Worker وCapacitor وملفات سير العمل وأيقونات PNG. افتح المعاينة عبر `http://127.0.0.1:4173`.

## Android

يستخدم المشروع Capacitor 8.6.2. يبني سير العمل APK موقّعاً عند ضبط أسرار التوقيع الأربعة، وينشره في GitHub Releases مع رابط دائم لآخر إصدار. وعند عدم ضبطها يبني APK تجريبياً (Debug) كـ Artifact لمدة 30 يوماً فقط.

## النشر

يستخدم `.github/workflows/build-and-deploy.yml` للنشر إلى GitHub Pages وإنشاء APK. يجب تفعيل Pages مرة واحدة من إعدادات المستودع واختيار `GitHub Actions` كمصدر النشر، ثم إعادة تشغيل الـ Workflow.


## تحديثات نسخة نوفمبر 2026

- تبدأ قاعدة المعالم بـ 16 سجلاً أساسياً، ويضيف فهرس الموسوعة ثلاثة سجلات ليصبح الإجمالي 19 بطاقة. وتعرض البطاقات الارتفاع بوصفه غير موثق ميدانياً ما لم يتوفر مرجع صالح.
- يحتوي الخط الزمني على سبع محطات، منها محطة 1915م المنفصلة عن انتفاضة 1919م. يميز بين الإحالات المنشورة والروايات المحلية التي تحتاج إلى توثيق.
- يحفظ مؤشر الاستكشاف والمفضلة والبيانات الإضافية داخل المتصفح نفسه.
- تعرض الصفحة دليلاً موسمياً إقليمياً للبن وإمطار المرتفعات. لا يمثل جدولاً زراعياً خاصاً بكل قرية ولا تنبؤاً جوياً.
- عند توفر Service Worker أحدث، يظهر إشعار تحديث. لا ينتقل التطبيق إلى النسخة الجديدة إلا بعد ضغط المستخدم، ولا تُمسح بيانات `localStorage`.

## ربط Supabase

1. أنشئ مشروعاً من [لوحة Supabase](https://supabase.com/dashboard/projects).
2. نفّذ `supabase/schema.sql` مرة واحدة في SQL Editor.
3. من إعدادات المشروع انسخ Project URL وPublishable key، ثم ضعهما في `www/supabase-config.js` داخل `url` و`anonKey`، أو استخدم نموذج إعداد الاتصال داخل التطبيق لكل جهاز.
4. لا تنسخ مفتاح `secret` أو `service_role` إلى أي ملف عام.
5. أنشئ حساب المشرف في Authentication → Users، ثم نفّذ تعليق ترقية المشرف الموجود في نهاية ملف SQL مع البريد نفسه. سجّل الخروج ثم الدخول مجدداً ليحمل JWT الدور الجديد.

المفتاح العام وحده لا يفعّل المزامنة؛ يجب إنشاء مشروع Supabase وتشغيل المخطط وإدخال بيانات الاتصال أولاً.

## لوحة الإشراف

الرمز الافتراضي عند أول استخدام هو `1234`. غيّره من داخل اللوحة. يُخزّن مشتق PBKDF2 مملح بدلاً من الرمز النصي. القفل حاجز استخدام محلي فقط؛ يستطيع مستخدم يملك وصولاً إلى أدوات المطور أو بيانات المتصفح تجاوزه. لا تضع فيه بيانات سرية ولا تستخدمه بديلاً عن مصادقة خادمية.

## Android: ترقيم الإصدار والتوقيع

يرفع سير العمل `versionCode` تلقائياً من رقم تشغيل GitHub Actions. ينشئ APK موقعاً وإصداراً دائماً في GitHub Releases فقط عند تهيئة مفاتيح التوقيع الأربعة التالية في Settings → Secrets and variables → Actions:

- `KEYSTORE_BASE64`
- `KEYSTORE_PASSWORD`
- `KEY_ALIAS`
- `KEY_PASSWORD`

أنشئ keystore مرة واحدة واحتفظ بنسخة احتياطية آمنة. استخدم keystore نفسه لكل الإصدارات اللاحقة. لا ترفع ملف keystore أو كلمات مروره إلى المستودع أو المحادثة. عند غياب الأسرار، يبني سير العمل APK تجريبياً ويضعه في Actions Artifacts لمدة 30 يوماً، ولا ينشئ Release دائماً. عند تفعيل الأسرار وإنشاء أول Release موقع، يكون رابط التنزيل الدائم لآخر إصدار هو `https://github.com/baraagpt6-droid/hubaish-smart-guide./releases/latest/download/hubaish-smart-guide.apk`.

تنبيه التوافق: نسخ APK التجريبية السابقة التي بُنيت بمفتاح debug مؤقت لا يمكن ضمان تحديثها فوق نسخة موقعة بمفتاح جديد. قد تحتاج إلى إزالة النسخة التجريبية القديمة قبل تثبيت أول إصدار موقع. بعد ذلك، يحافظ استخدام keystore نفسه على قابلية تثبيت التحديث فوق الإصدار الموقع السابق.
